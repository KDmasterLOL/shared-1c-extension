# Классификация модулей SharedToolkit

Экспортированные процедуры и функции в области `ПрограммныйИнтерфейс` образуют публичный API соответствующего общего модуля. Невыведенные в `Экспорт` процедуры и функции остаются внутренними. Классификация ниже отражает прямые зависимости исходного BSL; она не обещает совместимость с любой конфигурацией.

## Переносимое ядро

| Модуль | Назначение | Прямые зависимости SharedToolkit | Зависимость от метаданных конфигурации или БСП |
|---|---|---|---|
| `SharedToolkit_Значения` | Проверка типов и заполненности, диагностика значений | Нет | Нет |
| `SharedToolkit_Коллекции` | Операции над коллекциями и преобразования | `SharedToolkit_Значения` | Нет |
| `SharedToolkit_JSON` | Чтение JSON | Нет | Нет |
| `SharedToolkit_Математика` | Простые математические операции | Нет | Нет |

Переносимое ядро не должно обращаться к прикладным пространствам метаданных, БСП или адаптерным модулям. `tools/verify_snippet_migration.ts` проверяет этот инвариант для прямых ссылок в BSL.

## Границы исполнения кода

`SharedToolkit_Коллекции.ФильтроватьКолонки` принимает строку фильтра как исполняемое выражение BSL. Это совместимый динамический контракт, а не декларативное описание фильтра: строку может задавать только разработчик, и она не должна поступать из пользовательского ввода, данных базы, настроек, HTTP-ответов или другого недоверенного источника. Для обычного отбора используйте массив или другую поддерживаемую коллекцию имён колонок.

`SharedToolkit_Интеграция.ВыполнитьPython` запускает процесс ОС на сервере. Пути к интерпретатору и сценарию должны задаваться разработчиком или администратором и проверяться по принятой в среде политике размещения исполняемых файлов. Функция проверяет только строковый тип и непустое значение; происхождение пути должен гарантировать вызывающий код. Аргументы сценария передаются программе как строки, а допустимые значения обязан проверять сам сценарий.

Платформенные правила безопасности при запуске приложений требуют контролировать формирование команд и их данные: [Стандарт «Безопасность запуска приложений»](https://its.1c.ru/db/content/v8std/src/600/i8100774.htm). Для динамического исполнения BSL также применяются ограничения стандарта по [исполнению внешнего кода](https://its.1c.ru/db/content/v8std/src/600/i8100669.htm).

## Платформенные и инфраструктурные модули

| Модуль | Назначение и фактическая граница |
|---|---|
| `SharedToolkit_Формы` | Клиентские операции с формами. Использует платформенный контекст формы; не зависит от метаданных УТ/КА. |
| `SharedToolkit_Файлы` | Клиентские диалоги и серверные операции с временным хранилищем; журналирует ошибки через `SharedToolkit_ЖурналРегистрации`. |
| `SharedToolkit_Интеграция` | Вызов Python и обмен через XBase; использует платформенную файловую систему и журнал регистрации. Требует соответствующую среду исполнения. |
| `SharedToolkit_ЖурналРегистрации` | Запись в журнал регистрации платформы. API записи для дополнительных обработок вызывает БСП `ДополнительныеОтчетыИОбработки`. |
| `SharedToolkit_Пользователи` | Проверка членства в группах пользователей и доступа; ожидает метаданные групп `ГруппыПользователей` и `ГруппыДоступа` в целевой конфигурации. |

## Адаптеры БСП и конфигураций

| Модуль | Классификация | Прямые зависимости |
|---|---|---|
| `SharedToolkit_БСП` | Адаптер БСП | `БлокировкаРаботыСВнешнимиРесурсами` |
| `SharedToolkit_Версионирование` | Адаптер конфигурации с подсистемой версий | `РегистрСведений.ВерсииОбъектов` |
| `SharedToolkit_ВнешниеОбработки` | Адаптер БСП и метаданных дополнительных отчетов | `СтандартныеПодсистемыСервер`, `ДополнительныеОтчетыИОбработки`, метаданные `ВариантыОтчетов`; API работы с формами имеет клиентский контекст |
| `SharedToolkit_ДополнительныеСвойства` | Адаптер БСП дополнительных свойств | `УправлениеСвойствами`, `ДополнительныеСведения`; зависит от `SharedToolkit_Коллекции` и `SharedToolkit_Значения` |
| `SharedToolkit_КонтрагентыУТ` | Адаптер УТ/КА | `ОбщегоНазначенияУТКлиентСервер`, метаданные контрагентов и контактной информации |
| `SharedToolkit_ДокументыУТ` | Адаптер УТ/КА | Документы, перечисления и табличные части УТ/КА; журналирует ошибки через `SharedToolkit_ЖурналРегистрации` |
| `SharedToolkit_ГТД` | Адаптер оформления импортной таможенной декларации в УТ | Документы, справочники, перечисления и планы видов характеристик УТ; зависит от `SharedToolkit_JSON` и `SharedToolkit_Коллекции` |

Эти зависимости намеренно остаются в явно названных адаптерах. Универсальные модули не выполняют скрытый поиск прикладных объектов и не подменяют отсутствующие API пустым результатом. При переносе следует включать только те адаптеры, чьи зависимости существуют в целевой конфигурации. Проверка XML через `onec meta validate` подтверждает структуру источника, но не наличие перечисленных метаданных и подсистем в произвольной базе.
